# 个人数据镜子 设计文档

日期：2026-06-07

## 目标

一个本地优先的桌面应用，静默记录电脑活动（窗口切换、输入统计、浏览域名），每天生成一张"角色卡"——一幅从数字痕迹中长出来的自画像。系统与用户共同发现"我是谁"。

不是效率工具。不是监控工具。是一面镜子。

## 范围

### 首版：仅桌面端

只追踪电脑活动。不碰手机、不碰云端、不注册账号。

### 采集什么

| 维度 | 采集 | 不采集 |
|------|------|--------|
| 窗口活动 | 前台应用名、窗口标题（截断至50字）、持续时长 | 屏幕截图、窗口内容 |
| 输入统计 | 打字字数、删除字数、回车次数、输入节奏 | 具体打了什么字 |
| 浏览器 | 域名、页面标题、停留时长 | 完整 URL、页面内容、表单输入 |
| 时间段 | 逐小时的活跃时段分布 | — |

### 明确不做

- 不记剪贴板内容（只记"复制过"这个动作）
- 不记键盘输入内容
- 不记完整 URL
- 不录屏、不开摄像头、不碰麦克风
- 不联网同步、不注册账号
- 不做手机端

### 后续迭代

数据模型预留跨端导入接口。未来肖像将是完整的。

## 生长的画像

### 核心机制

系统维护一份"用户画像 JSON"，持续生长。每天生成角色卡后，AI 有权限更新这份画像：

```
第1天： { 基础作息: "夜型", 核心工具: ["VS Code", "Chrome"] }
第7天： { 基础作息: "夜型但午前效率高", 核心工具: [...],
          行为模式: "连续工作2小时后注意力碎片化" }
第30天：{ 完整作息曲线, 工具偏好排名, 拖延触发模式,
           高效窗口, 反复出现的主题, 行为一致性评分 }
```

### 三轮关系阶段

画像完整度决定 AI 的语气和话语权：

| 阶段 | 画像状态 | 语气 | 有权做什么 |
|------|---------|------|-----------|
| 观察期（第1-7天） | 碎片 | 陈述式，不做判断 | "昨天你在 Chrome 上花了 6 小时" |
| 熟悉期（第8-21天） | 轮廓清晰 | 对照式，引用历史 | "你上周说要少刷 Twitter，昨天你又看了 3 小时" |
| 亲密期（第22天起） | 精确 | 推动式，给建议 | "以我对你的了解，下午 2 点是你最脆弱的时段，建议..." |

阶段自动推进，依据数据量 + 行为一致性。AI 可在信心度下降时建议回退。

用户可随时暂停推进、冻结画像、删除任意维度。

## 每日角色卡

### 卡片结构

每张卡片固定几个区块：

1. **今日角色名** — AI 起的代号（5-12字，如"四处张望的猫"）
2. **行为素描** — 200-400字，自然学家口吻。AI 根据昨天信息量自行决定长短
3. **新的拼图碎片** — "我们今天对自己多了解了一点：..."（共同发现的叙事）
4. **阶段反馈** — 陈述/对照/建议，视所处阶段而定
5. **信心度** — 0-1。低于 0.5 时卡片标注"今天的数据比较模糊"

### 送达方式

- **早餐日报**（必选）：每天早上固定时间推送，像看天气预报一样看昨天的自己
- **随机轻推**（可选，用户可开关）：偶尔下午拍拍你。频率：偶尔/很少/关

## AI 管道

### 系统人格（固定不变）

```
你是一个数字自然学家。你在观察一个人类在电脑前的数字痕迹。
你的任务不是监控，而是理解。
你的语气像写田野观察日记——好奇、准确、不评判。
你永远不恭维、不说废话、不假装了解你不知道的东西。
你的知识来源仅限于提供给你的行为数据，你不推测数据之外的事。
当你不确定时，你直接说"这部分数据不足以判断"。

你不是在观察一个已知的对象。用户自己对"自己是什么样的人"也只有碎片。
你和他一起发现。你发现的部分用"我们"来表述。
```

### 每日角色卡生成（每天触发一次）

**输入：** 昨日行为摘要 + 当前画像 JSON + 当前阶段

**行为摘要格式（从原始日志压缩）：**
```
时间段      | 主应用      | 输入(字) | 删字率 | 浏览域名
08:30-09:00 | 微信        | 320      | 8%     | -
09:00-11:30 | VS Code     | 2100     | 22%    | stackoverflow.com(3)
11:30-12:00 | Chrome      | 80       | 5%     | twitter.com, bilibili.com
...
```

**输出：** 结构化 JSON，包含 `roleName`、`sketch`、`newPuzzle`、`feedback`、`confidence`

### 画像更新（同一次 LLM 调用，紧随卡片生成）

AI 收到刚生成的卡片 + 当前画像，判断是否更新：

```json
{
  "additions": [{"dimension": "下午自制力", "observation": "下午4点后删字率飙升，窗口切换频率增加3倍"}],
  "modifications": [{"dimension": "高效时段", "updatedTo": "上午9-11点（连续3天确认）"}],
  "removals": ["之前标记的'上午效率低'——近一周数据不支持此判断"],
  "stageRecommendation": "stay" | "advance" | "regress"
}
```

画像维度不做预定义。AI 自行决定加什么、删什么。这是拼图"自己长出来"的关键。

### 阶段切换逻辑

- `confidence` 连续 3 天低于 0.4 → AI 建议回退
- 画像连续 7 天无新增维度 → AI 提示"我对你的了解似乎停滞了"
- 设置面板可手动锁定/冻结阶段

## 数据隐私与用户控制

### 存储

- 所有数据只存本机：`~/Documents/PersonalMirror/`
- 一个 SQLite 文件存原始日志 + 画像 + 卡片历史
- 一个 Markdown 文件夹存可读的角色卡归档

### 用户能做什么

| 操作 | 方式 |
|------|------|
| 暂停/恢复采集 | 托盘菜单一键切换 |
| 预览今日已采集 | 设置面板 |
| 删除任意一天 | 卡片详情页删除，同时删除卡片和对应原始日志 |
| 删除任意画像维度 | 画像面板点叉移除 |
| 一键清空 | 设置面板，回到新用户状态 |
| 导出/导入画像 | JSON 导出，预留未来跨端导入接口 |

### 隐私红线

- 不存剪贴板内容（只记"复制过"这个布尔值）
- 不存键盘内容（只记字数、删字率、输入节奏）
- 浏览只记域名，不记完整 URL、不记页面内容
- 窗口只记应用名 + 标题前50字（剔除可能含敏感信息的文件路径）
- LLM API 调用：只传行为摘要 + 画像，不传原始日志

## 界面

只有两个界面。

### 桌面挂件（日常用）

- 透明常驻胶囊窗口（默认桌面右上角，可拖拽）
- 收起态：半透明小条，只显示今日角色名
- 悬停：变亮，暗示可交互
- 双击：展开为完整角色卡，可滚动、翻阅历史、进入设置

### 设置面板（偶尔用）

从挂件设置按钮或托盘菜单打开：

- **API 配置**：填 LLM API key、选模型、测试连接
- **采集设置**：开关采集、忽略的应用/域名列表
- **推送设置**：早餐日报时间、随机轻推开关 + 频率
- **数据管理**：预览今日采集、查看画像、导出/清空/删除

### 设计原则

- 不需要的时候零存在感
- 需要的时候信息直接到手
- 不做动画、不做复杂交互、不做新手引导

## 技术架构

```
┌─────────────────────────────────────┐
│          Electron 桌面壳             │
│  ┌──────────┐  ┌─────────────────┐  │
│  │ 后台采集器 │  │  卡片查看器      │  │
│  │（静默运行）│  │  （透明桌面挂件） │  │
│  └─────┬────┘  └────────┬────────┘  │
│        │                │           │
│  ┌─────┴────────────────┴────────┐  │
│  │       本地存储 (SQLite)         │  │
│  │  - 行为日志  - 用户画像 JSON    │  │
│  │  - 卡片历史  - 设置            │  │
│  └──────────────┬────────────────┘  │
│                 │                   │
│  ┌──────────────┴────────────────┐  │
│  │    AI 调度器（定时任务）        │  │
│  │  凌晨读昨日数据 → 调 LLM API   │  │
│  │  → 生成卡片 → 更新画像 → 存盘  │  │
│  └───────────────────────────────┘  │
└─────────────────────────────────────┘
```

| 模块 | 职责 | 技术 |
|------|------|------|
| 后台采集器 | 监听窗口切换、统计输入、记录浏览域名 | Electron 主进程 + macOS 辅助功能 API |
| 本地存储 | 存原始行为日志、用户画像 JSON、卡片历史、设置 | better-sqlite3（同步、无服务器） |
| AI 调度器 | 每日触发、构造 prompt、调 LLM、解析结果 | node-cron + 用户自备 API key |
| 卡片查看器 | 透明桌面挂件，翻阅历史卡片、开关随机轻推 | React + 透明 BrowserWindow |

## 验收标准

- [ ] 应用启动后开始静默采集
- [ ] 采集覆盖：前台应用、窗口标题、输入统计（打字/删字数）、浏览域名
- [ ] 键盘内容、剪贴板内容、完整 URL 均不做任何存储
- [ ] 托盘菜单可暂停/恢复采集
- [ ] 每天早上在用户设定时间，通过 LLM API 生成一张角色卡
- [ ] 卡片包含：角色名、行为素描、新的拼图碎片、阶段反馈、信心度
- [ ] 用户画像 JSON 随天数增长——AI 自主添加、修改、删除维度
- [ ] 关系阶段根据画像完整度和信心度自动推进或回退
- [ ] 桌面挂件收起时显示角色名，双击展开完整卡片
- [ ] 挂件可翻阅历史卡片
- [ ] 设置面板：配 API key、选模型、设采集排除项、设推送时间、开关随机轻推
- [ ] 用户可预览今日采集、删除任意一天、移除画像维度、一键清空
- [ ] 随机轻推可开关，并遵守频率设定
- [ ] 所有数据不出本机，除 LLM API 外无任何网络请求
- [ ] 导出功能产出 JSON，可供未来手机端导入
