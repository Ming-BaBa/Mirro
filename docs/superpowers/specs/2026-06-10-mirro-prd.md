# Mirro — 产品需求文档

日期：2026-06-10（v1.0 更新）

## 产品定位

Mirro 是一个本地桌面自我认知工具。它静默记录用户的电脑使用行为（窗口切换、输入节奏、浏览域名），通过 AI 分析帮助用户发现无意识的行为模式——比如什么时候在摸鱼、摸了多久、高效时段在哪里。

**不是效率工具，不是监控工具，是镜子。**

用户通过一只住在桌面上的小猫 Mirro 与系统互动。猫以陪伴的方式传递洞察，而不是生硬地指出问题。卡片、推送、皮肤等是提供情绪价值的附属功能。

**使用场景：** 个人本地使用，后期可能开源到 GitHub 供他人本地部署。所有数据不上云，LLM 调用由用户自备 API Key。

## 核心功能

### 1. 行为采集

静默运行，无感记录。

| 维度 | 采集 | 不采集 |
|------|------|--------|
| 窗口活动 | 前台应用名、窗口标题（≤50字） | 屏幕截图、窗口内容 |
| 输入统计 | 打字字数、删除字数、回车次数 | 具体按键内容（仅供实时动画） |
| 浏览器 | 域名（从标题解析） | 完整 URL、页面内容 |
| 时间 | 30 分钟时间段分布 | — |
| 打字内容 | 原始按键序列（经 PII 脱敏后用于文本还原） | 明文内容 |

**采集机制：** 每 3 秒轮询前台窗口（`active-win`），应用或标题变化时 flush 一个 segment。`uiohook-napi` 监听全局键盘事件，统计字数和删除数。

**隐私保护：** 正则脱敏（`sanitizer.ts`），移除 API Key、密码、Token、文件路径、Base64 等敏感模式。高符号比例行（>60%）自动丢弃。

**用户控制：** 托盘菜单一键暂停/恢复。可设置忽略的应用列表。

### 2. 每日角色卡

每天定时（用户设定，默认 08:00）通过 LLM 分析前一天的行为数据，生成一张角色卡。

**卡片结构：**

| 字段 | 说明 |
|------|------|
| `roleName` | 今日角色名（状态描述，如"深夜调试模式"） |
| `sketch` | 行为素描（200-400字，按时段客观描述） |
| `newPuzzle` | 新发现的拼图碎片（"今天对自己多了解了一点"） |
| `feedback` | 阶段反馈（观察期陈述 / 熟悉期对照 / 亲密期建议） |
| `confidence` | 信心度 0-1，低于 0.5 标注"数据模糊" |
| `imageBase64` | AI 生成的配图（可选，需配置图片 API） |

**送达方式：**
- 早餐日报（定时推送）
- 随机轻推（下午 14:00-18:00，概率触发，可开关）

**手动生成：** 设置面板支持"立即生成今日卡片"，带进度条和取消功能。

### 3. 用户画像

系统维护一份持续生长的用户画像。每天生成卡片后，AI 自主判断是否更新画像维度。

**画像维度由 AI 自行定义，不做预设。** 维度举例：`基础作息`、`核心工具`、`注意力分布`、`拖延触发模式`。

**每日画像更新输出：**
```json
{
  "additions": [{"dimension": "下午自制力", "observation": "4点后窗口切换频率增加3倍"}],
  "modifications": [{"dimension": "高效时段", "updatedTo": "上午9-11点（连续3天确认）"}],
  "removals": [],
  "stageRecommendation": "advance"
}
```

画像连续 7 天无新增维度时，卡片反馈中提示停滞警告。

用户可随时在设置面板中删除任意画像维度。

### 4. 三阶段关系

画像完整度决定 AI 的语气和话语权：

| 阶段 | 画像状态 | 语气 | 示例 |
|------|---------|------|------|
| 观察期 | 碎片 | 陈述式，不做判断 | "昨天你在 Chrome 上花了 6 小时" |
| 熟悉期 | 轮廓清晰 | 对照式，引用历史 | "你上周说要少刷 Twitter，昨天又看了 3 小时" |
| 亲密期 | 精确 | 推动式，给建议 | "下午 2 点是你最脆弱的时段" |

**阶段自动推进/回退。** `portrait-manager` Agent 根据数据质量和画像完整度给出 `advance` / `regress` / `hold` 建议，系统自动应用。

### 5. 桌面宠物（Widget）

一只 APNG 动画小猫常驻桌面，作为用户与系统的交互入口。

**动画系统：** 16 种动画状态，部分由键盘触发：

| 触发 | 动画 |
|------|------|
| 日常待机 | idle |
| 按退格 | crying |
| 按回车 | enter |
| 按 T/Y | t / y |
| 按 E/R | er |
| 按 Z/X/A/S/D/C/F | zxasdc |
| 按 S/V/G | svg |
| 按 B/N/H | bnh |
| 按 J/K/L/M/U/I/O/P | jklm |
| 按 Q/W | qw |
| 按修饰键（Ctrl/Alt） | control |
| 按空格/Cmd | space |
| 连续打字30+后停3秒 | tired |
| 随机待机（10s-5min） | idle2（懒腰）/ eat（思考吃什么） |

**胶囊栏：** 实时显示最近按键字符流。

**交互：**
- 拖拽移动，松手自动吸附到屏幕边缘
- 双击打开卡片窗口
- 点击角色弹出气泡菜单（聊天气泡 + 设置齿轮）
- 支持锁定/解锁、调整尺寸

### 6. 陪伴聊天

用户可以跟 Mirro 聊天。猫以自己的人设回答，了解用户的画像和行为习惯。

**聊天特性：**
- 猫的角色由用户选择的性格标签决定（25 个预设标签可选）
- 行为红线：拒绝专业问题、拒绝擦边/敏感话题、被问是否 AI 时保持模糊
- 对话上下文保留最近 10 轮
- 关系阶段影响亲密度（观察期拘谨 → 亲密期撒娇）
- 用户画像和近 7 天记忆作为知识库注入 system prompt

**对话持久化：** 当天对话保存到文件，关闭窗口不丢失。夜间生成后自动清空，第二天重新记录。

### 7. 记忆系统

猫拥有短期和长期记忆。

| 类型 | 存储 | 生命周期 |
|------|------|----------|
| 对话上下文 | 内存（useState） | 关闭窗口清空（已持久化到文件） |
| 当天聊天记录 | `~/Documents/Mirro/chats/YYYY-MM-DD.json` | 夜间总结后清空 |
| 长期记忆 | `~/Documents/Mirro/memories/YYYY-MM-DD.json` | 最近 7 天，总大小 ≤ 30KB，超出自动删除最旧的 |
| 用户画像 | SQLite `portrait` + `portrait_meta` 表 | 持久化，用户可手动删除维度 |

每次聊天时，用户消息会被追加到当天记忆。夜间生成时，画像更新已作为最重要的信息保留，原始行为日志和聊天记录在生成完成后自动清除。

## AI 管道（Agent 架构）

### 整体流程

```
行为数据（SQLite）
      │
      ▼
┌─────────────────────────────────────────┐
│          每日生成管道（scheduler.ts）      │
│                                         │
│  1. 加载数据                             │
│       │                                 │
│       ▼                                 │
│  2. PII 脱敏（sanitizer.ts）            │
│       │                                 │
│       ▼                                 │
│  3. Agent 1: 文本还原器（interpreter）   │
│     拼音 → 中文内容摘要                  │
│       │                                 │
│       ▼                                 │
│  4. Agent 2: 行为分析师（analyst）       │
│     行为数据 + 文本摘要 + 画像 → 角色卡   │
│       │                                 │
│       ▼                                 │
│  5. 配图生成（可选）                      │
│       │                                 │
│       ▼                                 │
│  6. Agent 3: 画像管家（portrait-manager）│
│     行为数据 + 画像 → 画像更新 + 阶段建议 │
│       │                                 │
│       ▼                                 │
│  7. 阶段推进 + 数据清理                  │
│                                         │
└─────────────────────────────────────────┘
```

### Agent 1：文本还原器（interpreter）

**输入：** 脱敏后的原始按键文本（≤4000字）
**输出：** 中文内容摘要（100-200字）

原始按键经过中文输入法后呈现为拼音序列。此 Agent 根据应用上下文（VS Code = 代码注释，Chrome = 搜索关键词，微信 = 聊天消息）将拼音还原为有意义的中文摘要。

**实现：** 直接调用 `callLLM()`，不使用工具循环。

### Agent 2：行为分析师（analyst）

**输入：** 行为摘要表格 + 用户画像 + 文本还原结果
**输出：** 结构化 JSON（`roleName`、`sketch`、`newPuzzle`、`feedback`、`confidence`）

四个分析维度：
1. **工作效率** — 输入量、删字率、专注时长
2. **话题兴趣** — 还原文本 + 浏览域名
3. **行为节奏** — 时间分布、切换频率
4. **状态推断** — 专注/碎片化/探索/调试

规则：`roleName` 是状态描述不是动物名，`sketch` 必须客观按时段描述，不确定时说"数据不足以判断"。

**实现：** 直接调用 `callLLM()`，内置 `calc_statistics` 工具定义但未实际使用工具循环。

### Agent 3：画像管家（portrait-manager）

**输入：** 行为摘要 + 当前画像维度列表
**输出：** `{ additions, modifications, removals, stageRecommendation }`

核心原则：
- 优先修改现有维度而非新增
- 修改时将新观察融入现有描述（累积式）
- 维度名要宽泛（"输入习惯"、"活跃时段"）
- 数据与画像一致时输出空数组
- 每次变更必须有真实信息增量

**实现：** 直接调用 `callLLM()`，无工具定义。

### 聊天 Agent

**非管道式。** 用户发起时实时调用 `callLLM()`。

**System Prompt 模板：**
```
你是 Mirro，一只住在主人电脑桌面上的可爱小猫。
{personality}          ← 用户选择的性格标签
语气：简短口语化，偶尔加"喵~"，回复控制在100字以内。
行为红线：[4条]
{portrait}             ← 用户画像维度
{memories}             ← 近7天记忆
当前关系阶段：{stage}   ← 阶段对应的语气指引
```

### LLM 支持的供应商

| 供应商 | API 格式 |
|--------|----------|
| Anthropic | 原生 Messages API |
| OpenAI | OpenAI Compatible |
| DeepSeek | OpenAI Compatible |
| GLM（智谱） | OpenAI Compatible |
| Kimi（月之暗面） | OpenAI Compatible |
| Doubao（字节跳动） | OpenAI Compatible |
| Apimart | OpenAI Compatible |

图片生成：Apimart + Gemini（`gemini-3-pro-image-preview`），需单独配置 `imageApiKey`。

```
│  │  └──────────────────────────────────────────┘  │  │

│  └────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────┘

         外部依赖
    ┌──────────────┐
    │  LLM APIs    │  ← 用户自备 API Key
    │  (7 供应商)   │
    └──────────────┘
```

| 模块 | 职责 | 技术 |
|------|------|------|
| 采集器 | 监听窗口切换、统计输入、记录浏览域名 | `active-win` + `uiohook-napi`（macOS 辅助功能 API） |
| SQLite | 行为日志、角色卡、画像、设置 | `better-sqlite3`（同步，WAL 模式） |
| 文件存储 | 记忆摘要、聊天记录 | JSON 文件，自动清理 |
| Agent 管道 | 文本还原 → 行为分析 → 画像更新 | 3 个独立 Agent，串行调用 `callLLM()` |
| 调度器 | 每日定时触发生成管道 | `node-cron`，每分钟检查是否匹配设定时间 |
| 桌面宠物 | APNG 动画猫 + 胶囊栏 + 按键动画 | React + 透明 BrowserWindow |
| 设置面板 | API 配置、采集控制、画像管理、性格选择 | React + 6-Tab 布局 |
| 聊天窗口 | 实时对话、历史加载、上下文管理 | React + IPC |
| LLM 客户端 | 多供应商适配、工具调用、代理检测 | 原生 Anthropic API + OpenAI Compatible |

### 数据目录

```
~/Documents/Mirro/
  mirro.db              ← SQLite 数据库
  memories/             ← 长期记忆（≤30KB，自动清理）
    2026-06-10.json
    2026-06-09.json
  chats/                ← 当天聊天（夜间清空）
    2026-06-10.json
```

### 数据生命周期

```
实时采集 → behavior_log（SQLite）
              │
              ▼
夜间生成管道 → 角色卡（持久化）+ 画像更新（持久化）+ 记忆摘要（持久化）
              │
              ▼
清理 → 删除 behavior_log + chats（已提炼的信息保留，原始数据丢弃）
```

| 窗口 | 触发 | 特性 |
|------|------|------|
| 桌面宠物 | 启动自动显示 | 透明、置顶、无边框、可拖拽、吸附屏幕边缘 |

### 设置面板（6 个 Tab）

| Tab | 功能 |
|-----|------|
| 画像 📊 | 查看/删除画像维度，接受画像更新提案，导出 JSON，一键清空 |
| 今日 📅 | 今日采集统计，立即生成卡片（带进度条+取消），归档目录选择 |
| 外观 🎨 | 胶囊宽度（120-500px），角色高度（40-200px），皮肤选择（1个可用+3个展示位） |
| 角色 🐱 | 性格标签选择器（25个预设标签，如温柔/高冷/调皮等） |
| 推送 🔔 | 日报时间，随机轻推开关+频率 |
| API ⚙️ | LLM 供应商（7选1）+ 模型 + API Key + 连接测试，图片生成 API（可折叠） |

- 打开设置
- 暂停/恢复采集
- 退出
